# AGENTS.md

This file provides guidance to AI Agents when working with code in this repository.

**All project documentation lives in `project_docs/`.** Do not create docs elsewhere.

```
project_docs/
├── architecture/    # ADRs and system architecture notes
├── database/        # Schema decisions, migration plans, SQL seeds
├── design/          # Feature specs, design decisions, UX notes
└── *.md             # Top-level deployment guides and one-pagers
```

When an agent creates a spec, plan, design doc, or any reference document, it must be written to the appropriate `project_docs/` subdirectory:

- Architecture decisions → `project_docs/architecture/`
- Feature specs and design docs → `project_docs/design/`
- Database-related docs → `project_docs/database/`

**Do not** create `docs/`, `docs/superpowers/`, or any other documentation directory at the repo root.

The one versioned exception is `intent/`: short intent files (what is wanted, why, under which constraints) written before a spec, following Anthropic's AI-native SDLC loop (intent → spec → plan → diff → PR). They live beside the code because `project_docs/` is unversioned and the intent is the start of the audit trail.

## Development conventions

Read by the shared `sdlc-*` skills (`sdlc-intent`, `sdlc-spec`, `sdlc-bugfix`, `sdlc-ship`, from `baker-internal/skills/`); keep each line current when the process changes.

- Intents: `intent/<date>-<slug>.md` (versioned; see above).
- Specs: `project_docs/design/<date>-<slug>.md` (unversioned), header links the intent path and the issue number. Shape: Problem, Goals and non-goals, Decisions (one subsection per decision with its reason), Architecture, Acceptance criteria, Implementation plan, For the testing agent; `## As built` appended after the build.
- Typecheck: `npm run typecheck` (builds shared first; the backend imports `@nexus/shared`, so a stale `shared/dist` compiles against yesterday's types).
- Tests: backend `npm run --workspace=src/backend test`; frontend `npm run --workspace=src/frontend test`; memory daemon `npm --prefix src/memory-daemon test`; NexusCore `swift test` in `ios/NexusCore`. The iOS app target is not in CI and needs an Xcode simulator build, which Keith runs. The backend runs from `dist/`, so `npm run build` is part of verifying anything it serves.
- Known non-failures: the pi-runtime "orientation block" test depends on `~/.agents/skills` contents and fails on `main` too; a `JIRA_TOKEN` in the shell breaks the "unconfigured Jira" tests, so unset it for the run.
- Branches and commits: `feat/<slug>`, `fix/<slug>`, `docs/<slug>`; conventional messages with a scope, e.g. `feat(engines): …`.
- PR body: Summary / Verification / After merge. Link the intent, issue, and design doc; name every new config key, route, or Settings section. No "Generated by AGENT" lines.
- Merge: merge commits (`gh pr merge N --merge`), never squash; stacked branches break on squashed bases.
- Deploy: baker-pro runs the backend from launchd: `git pull && npm ci && npm run build && ./scripts/restart-backend.sh` (restart only: `launchctl kickstart -k gui/$(id -u)/com.k-sym.nexus-backend`); wait ~30 s before judging health. Name any new `~/.nexus/config.yaml` key in the PR.
- Gotchas: never stage `project_docs/**` from a script (git shows phantom deletes there on the laptop; check `git diff --stat` first). Migrations are additive; tables are left as tombstones because `~/.nexus/nexus.db` is the audit ledger. Shared types go in `src/shared/index.ts`. Any new write to an external system (GitHub, Monday, Jira) is confirm-gated in the UI and stays out of agent tool surfaces.

## Skills

The development loop is the shared `sdlc-*` set in `baker-internal/skills/` (install once per machine with its `link-skills.sh`). This repo adds two Idea Watcher skills in `.claude/skills/`, loaded automatically in Claude Code here; `./scripts/link-skills.sh` symlinks them into `~/.claude/skills` so the partner (which runs idea threads) sees them too.
